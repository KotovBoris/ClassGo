# COLOR.md — цвет и семантика интерфейса ClassGo

> Сдаваемый документ. Ресерч цветовых конвенций + предложение палитры для мини-аппа ClassGo
> (`miniapp/src/styles.css`). Компаньоны: [`DESIGN.md`](DESIGN.md) (контракт v2 «Бригадир»),
> [`UX_PLAYBOOK.md`](UX_PLAYBOOK.md) (§1/§2 — правила и анти-паттерны, §6 — находки).
> **Код не менялся** — это документ и предложение; реализация — отдельная подзадача.

---

## 0. TL;DR

Главная проблема: `--accent` (primary/главное действие) и `--stop` (отказ/опасность) — **один и тот же
красный `#B3121A`**. Пользователь читает каждую залитую кнопку как «ОТМЕНА/опасно». Решение — развести
два смысла в два токена:

- **главное действие** → глубокий синий/индиго `#1D4ED8` (белый текст, контраст 6.7:1);
- **деструктив/отказ/критическая ошибка** → остаётся красным `#B3121A`;
- **статусы «Сводка ответов»** (`--ok`/`--wait`/`--idle`/`--stop`) не трогаем — они уже правильные.

## 1. Главные конвенции (3–5 пунктов)

1. **Цвет = семантика, а не декор.** У primary/brand, danger/destructive, success, warning, neutral —
   разные роли, и они **не должны совпадать по значению**. Материал называет это «color roles»: роли
   назначаются от смысла элемента, а не от эстетики. Если главное действие и опасность одного цвета —
   смысл действия не считывается. ([Material Design 3 — Color roles](https://m3.material.io/styles/color/roles))

2. **Красный зарезервирован за деструктивом, ошибкой и срочностью.** Во всех крупных системах красный =
   «удалит/откажет/что-то уже сломано», но **не** «продолжить/создать/подтвердить». Красный primary —
   типичная ошибка новичков: «красиво выглядит» перевешивает «что кнопка говорит». Исключение — бренд,
   где красный сам по себе идентичность (Netflix, YouTube), но там красный не используется для
   нейтральных действий внутри продукта. ([GOV.UK Button](https://design-system.service.gov.uk/components/button/),
   [IBM Carbon Color](https://v10.carbondesignsystem.com/guidelines/color/usage/))

3. **Главное действие — один цвет, второстепенные — нейтральные.** GOV.UK прямо формулирует: у
   пользователя должна быть **одна** зелёная/главная кнопка на экран (зелёная «Start» — единственное
   главное действие), остальное — secondary-серое; красная warning-кнопка — только для финального
   подтверждения деструктивного действия. ([GOV.UK green button](https://design.tax.service.gov.uk/patterns-hmrc-govuk-team/green-button/))

4. **Не полагаться только на цвет.** Дальтонизмом страдают ~8% мужчин (0.5% женщин), чаще всего
   красно-зелёная форма (протанопия/дейтеранопия): красный и зелёный сливаются в один грязный тон.
   Любой смысл цвета дублируется текстом/иконкой/формой. ([Wikipedia — Color blindness](https://en.wikipedia.org/wiki/Color_blindness),
   [WCAG 1.4.1 Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html))

5. **Контраст — это и есть «читаемость».** Текст ≥ 4.5:1 (крупный ≥ 3:1), активные UI-элементы/иконки
   ≥ 3:1. Ниже — интерфейс не читается частью пользователей, что отдельно карается критериями доступности.
   ([MDN — WCAG Color contrast](https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Understanding_WCAG/Perceivable/Color_contrast))

## 2. Семантика цвета (сводка)

| Роль | Смысл | Типовой цвет | Где уместен |
|---|---|---|---|
| **Primary / brand** | главное действие, бренд | синий/индиго (у нас) | «Создать выезд», «Отпускаю ребёнка», CTA, ссылки, фокус |
| **Danger / destructive** | необратимое, отказ, ошибка | красный | «Удалить», отказ родителя, критическая ошибка, срочный дедлайн |
| **Success** | успех/готово | зелёный | «Готов», «согласие получено», оплачено |
| **Warning** | внимание/не готово | янтарный | «ждём билет», дедлайн приближается |
| **Neutral / muted** | вторичное, нет ответа | серый | «нет ответа», подписи, вторичные кнопки |
| **Info** | пояснение | синий/нейтральный | информационные алерты (НЕ красный) |

Токены должны быть **семантическими** (названы по роли, не по цвету): `--primary`, `--danger`,
`--success`, `--warning`, `--neutral`. Это позволяет перекрашивать, не трогая классы. Apple в HIG
называет это «semantic colors» (`systemRed` = деструктив, `systemBlue` = акцент/линки), а не
«#007AFF». ([Apple HIG — Color](https://developer.apple.com/design/human-interface-guidelines/color))

**Почему красный не годится для primary:** в интерфейсе красный уже загружен смыслом «стоп/ошибка/
опасность». Если им залиты обычные действия, у пользователя пропадает возможность быстро отличить
«продолжить» от «отменить» — это и когнитивная нагрузка, и риск случайного деструктивного клика, и
нарушение конвенций, к которым люди привыкли (Jakob's Law). Красный уместен только для деструктива.

## 3. Практики дизайн-систем (коротко)

- **Material Design 3** — роли `primary`/`secondary`/`tertiary`/`error` (+ `on-primary` и т.п.),
  `error` — отдельная роль, никогда не совпадает с `primary`. Динамический цвет подбирает их из
  бренда. ([M3 Color roles](https://m3.material.io/styles/color/roles))
- **Apple HIG** — `tint color` (акцент/линки, синий `systemBlue`), отдельная роль **destructive**
  (`systemRed`) для удаления/отмены. Деструктив всегда отделён от обычных действий.
  ([Apple HIG Color](https://developer.apple.com/design/human-interface-guidelines/color))
- **GOV.UK** — зелёная кнопка `#00703C` «Start» как **единственное** главное действие на экран;
  красный `#d4351c` — только для warning/deadly action. Чёткое правило «один primary, остальное
  серое». ([GOV.UK Button](https://design-system.service.gov.uk/components/button/),
  [GOV.UK Colour](https://design-system.service.gov.uk/styles/colour/))
- **IBM Carbon** — явные семантические токены: `$interactive`/primary = `#0f62fe` (синий),
  `$danger` = `#da1e28` (красный), `$support-01..04` = error/success/warning/info. Primary и danger
  **никогда не пересекаются**. ([Carbon Color usage](https://v10.carbondesignsystem.com/guidelines/color/usage/))
- **Shopify Polaris / Atlassian** — та же идея: `action` (primary, синий) отдельно от
  `critical`/`danger` (красный), статусы success/warning/info отдельными токенами.
  ([Atlassian Color](https://atlassian.design/foundations/color))
- **Bootstrap / Tailwind** — готовый семантический набор `primary/secondary/success/danger/warning/info`;
  `primary` по умолчанию синий (`#0d6efd`), `danger` — красный (`#dc3545`). Это «словарь», который
  пользователи уже знают. ([Bootstrap Colors](https://getbootstrap.com/docs/5.3/utilities/colors/),
  [Tailwind Colors](https://tailwindcss.com/docs/colors))

**Вывод из практик:** primary-синий + danger-красный + success-зелёный + warning-янтарный — это
де-факто стандарт, на котором пользователь «не думает».

## 4. Доступность (что проверить)

- **Контраст (WCAG 2.2):** обычный текст ≥ 4.5:1, крупный (18px+/14px bold+) ≥ 3:1, активные
  UI-элементы/иконки/фокус-кольца ≥ 3:1. ([MDN Color contrast](https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Understanding_WCAG/Perceivable/Color_contrast))
- **«Не полагаться только на цвет»** (SC 1.4.1): цвет дополняется текстом/иконкой/формой. У нас
  статусы уже имеют и текст («Готов: 12»), и подпись у места — это правильно.
- **Дальтонизм:** ~8% мужчин; красный/зелёный конфликт. Проверять через симулятор
  (протанопия/дейтеранопия). Красный «отказ» и зелёный «готов» визуально разделяются формой (badge с
  рамкой) и текстом — цвет никогда не единственный носитель.
- **Инструмент проверки контраста:** WebAIM Contrast Checker — https://webaim.org/resources/contrastchecker/

**Культурный контекст РФ/СНГ:** красный здесь одновременно и «официальная печать/важность» (откуда
взялась идея `--accent` как «распределительная отметка»), и «запрет/опасность/стоп» (знак
«нельзя»). Для аудитории учителей/родителей (публичный сектор, доверие к документам и согласиям)
приоритет — **недвусмысленность**: красный у кнопки «Создать приказ» читается как «не нажимай», что
подрывает доверие. Синий/индиго даёт «спокойную официальность» без риска считывания как запрета.

## 5. Что не так сейчас в ClassGo

1. **Primary-кнопки залиты красным.** `--accent: #B3121A` используется как фон `.kv-btn.primary`
   ([`styles.css:237`](../miniapp/src/styles.css:237)) — «Создать выезд», «Отпускаю ребёнка»,
   «Сформировать приказ» выглядят как деструктив. Это и есть баг №1.

2. **Акцент и опасность — один цвет.** `--accent` (#B3121A) **и** `--stop` (#B3121A) совпадают
   ([`styles.css:28`](../miniapp/src/styles.css:28), [`styles.css:36`](../miniapp/src/styles.css:36)). Красный
   одновременно значит «главное действие» и «отказ» — два противоположных смысла неразличимы.

3. **Информационный алерт красный.** `.kv-alert.info` берёт `border-left-color: var(--accent)` — то
   есть красную кромку ([`styles.css:675`](../miniapp/src/styles.css:675)). Инфо-сообщение читается как
   ошибка. (Ещё один симптом того, что «акцент = красный» протёк во все элементы.)

Красный при этом **уместен и остаётся** там, где он сейчас верный: `.kv-btn.danger`, `.kv-alert.err`,
`.kv-seat-RED`/`.dot-RED`/`.badge-RED` (отказ), `.kv-countdown.urgent` (срочный дедлайн).

## 6. Предлагаемая палитра (токены)

Разводим «акцент-действие» и «опасность» в разные токены. Статусы «Сводка ответов» не трогаем.

| Токен | Роль | Новое значение | Было | Почему |
|---|---|---|---|---|
| `--accent` | **primary / главное действие / бренд** | `#1D4ED8` | `#B3121A` | глубокий синий-индиго: «спокойная официальность», не конфликтует с красным деструктивом и с зелёным статуса |
| `--accent-ink` | primary hover/active, ссылки-акценты | `#1E40AF` | `#8F0E14` | темнее primary для нажатия; белый текст на нём 8.7:1 |
| `--stop` | **danger / отказ / критическая ошибка** | `#B3121A` (без изменений) | `#B3121A` | красный остаётся за деструктивом |
| `--ok` | success / готово | `#1F7A4C` (без изменений) | — | зелёный = «готов» |
| `--wait` | warning / ждёт билет | `#8A5A12` (без изменений) | — | янтарный = «внимание» |
| `--idle` | neutral / нет ответа | `#6F6A63` (без изменений) | — | серый = «нет данных» |

**Три варианта primary (выбрать один):**

| Вариант | HEX | Белый текст на нём | Оценка |
|---|---|---|---|
| **A. Индиго-синий (рекоменд.)** | `#1D4ED8` | 6.7:1 ✓ | спокойный, не спорит со статусами, читается как «официально, надёжно» |
| **B. Нави (строже)** | `#1E3A8A` | 10.3:1 ✓ | почти чернила (`--ink #1C1A17`) — рискует слиться с текстом и потерять роль акцента |
| **C. Глубокий зелёный** | `#00703C` | 6.2:1 ✓ | GOV.UK-стиль, НО конфликтует с `--ok #1F7A4C` статуса «готов» → пришлось бы перекрашивать все статусы |
| (доп.) Тёплый графит | `#374151` | 10.3:1 ✓ | безопасный, но слабый «акцент»; подходит только как строгий запасной |

**Рекомендация — вариант A (`#1D4ED8`).** Он единственный, кто не конфликтует ни с красным
деструктивом, ни с зелёным/янтарным/серым статусов, и при этом считывается как «нажать здесь».

### Правило «что во что красить»

| Элемент интерфейса | Токен | HEX | Почему |
|---|---|---|---|
| Главная кнопка (`«Создать выезд»`, `«Отпускаю ребёнка»`) | `--accent` (фон), белый текст | `#1D4ED8` | единственный primary на экран |
| Вторичные кнопки | нейтральный `--sheet`/`--raised` + `--ink` | — | не конкурируют с primary |
| **Отказ родителя / удалить / отменить** | `--stop` | `#B3121A` | деструктив = красный, отделён от primary |
| Критическая ошибка (`kv-alert.err`) | `--stop` | `#B3121A` | красный = ошибка |
| Информационный алерт (`kv-alert.info`) | `--accent` | `#1D4ED8` | инфо = бренд-синий, НЕ красный |
| Ссылка / link-кнопка | `--accent-ink` | `#1E40AF` | синяя ссылка |
| Фокус-кольцо (`:focus-visible`) | `--accent` | `#1D4ED8` | видимый синий контур |
| Статус «готов» (GREEN) | `--ok` | `#1F7A4C` | зелёный, только цвет + текст |
| Статус «ждёт билет» (YELLOW) | `--wait` | `#8A5A12` | янтарный |
| Статус «нет ответа» (GREY) | `--idle` | `#6F6A63` | серый |
| Статус «отказ» (RED) | `--stop` | `#B3121A` | красный = отказ |
| Срочный дедлайн (`kv-countdown.urgent`) | `--stop` | `#B3121A` | срочность = красный |

**Главное правило:** красный (`--stop`) — **только** для деструктива/ошибки/срочности и статуса
«отказ». Всё, что «ведёт вперёд», — синий `--accent`. Цвета статусов не пересекаются с primary:
у них свои 4 цвета, у primary — один отдельный.

## 7. Чек-лист «цвет перед сдачей»

- [ ] `--accent` (primary) ≠ `--stop` (danger) по значению — разные смыслы, разные цвета.
- [ ] Красный используется **только** для деструктива/ошибки/срочности и статуса «отказ».
- [ ] Информационные алерты НЕ красные (синий/нейтральный).
- [ ] Один primary-цвет на экран; вторичные кнопки — нейтральные.
- [ ] Контраст всех пар ≥ 4.5:1 (текст) / ≥ 3:1 (UI), проверен в WebAIM.
- [ ] Статусы «Сводка ответов» различимы не только цветом: текст «Готов/Ждёт билет/Нет ответа/Отказ» + форма
      (badge с рамкой, точка, место) — цвет дублируется.
- [ ] Прогнан симулятор дальтонизма (протанопия/дейтеранопия): «отказ» отличим от «готов» по форме/тексту.
- [ ] `.kv-btn.danger` визуально отделён от `.kv-btn.primary` (и по цвету, и по месту).
- [ ] Фокус-кольцо видимое (синий `--accent`), не красное.

## 8. Влияние на критерии жюри

- **UX/UI (~20%)**: правильная цветовая семантика — это «Aesthetic-Usability Effect» и Jakob's Law
  (интерфейс ведёт себя как привычные системы). Разведение primary/danger напрямую закрывает
  анти-паттерны «цвет как носитель смысла» и «деструктив равнозначен главному» из
  [`UX_PLAYBOOK.md`](UX_PLAYBOOK.md) §2/§6.
- **Доступность**: контраст ≥ 4.5:1 и «не только цветом» — это WCAG 2.2 SC 1.4.3 и SC 1.4.1. Красный
  primary — это и семантическая ошибка, и риск для красно-зелёного дальтонизма; исправление даёт
  очко за доступность.
- **Доверие к домену**: учителя/родители работают с юридически значимыми согласиями; отсутствие
  «красного шума» повышает восприятие надёжности.
