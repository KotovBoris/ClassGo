# UX Playbook ClassGo — золотые правила и типичные ошибки интерфейса

> Сдаваемый документ. Назначение: зафиксировать «экспертизу UX из интернета» в виде переиспользуемого
> плейбука (правила → анти-паттерны → ошибки по уровням → чек-лист) и прогнать по нему мини-апп ClassGo.
> Источники — под каждым блоком и в конце. Компаньон этого файла — скилл `work/skills/ux-review/SKILL.md`
> (симлинк `~/.roo/skills/ux-review`), который применяет плейбук к любому UI, не только ClassGo.

Сокращения приоритетов правок (для §6 и TODO): **P0** — ломает понимание/действие/доступность, чинить до
защиты; **P1** — заметно улучшает удобство, чинить если есть время; **P2** — полировка, не критично.

## 1. 12 золотых правил (коротко и по делу)

Каждое правило: формулировка · почему · как проверить. База — NN/g 10 usability heuristics + Laws of UX +
GOV.UK + Apple HIG + Material 3 + WCAG 2.2.

| # | Правило | Почему | Как проверить |
|---|---|---|---|
| 1 | **Показывай состояние системы** — после каждого действия пользователь должен видеть, что произошло, и что происходит сейчас | Без обратной связи пользователь повторяет клик, сомневается, выходит | Каждая кнопка с эффектом даёт `loading/disabled/результат`; у фоновых операций есть индикатор/тост |
| 2 | **Говори языком пользователя, не системы** — слова предметной области, порядок «как в жизни» | Интерфейс понятен без перевода «что это за поле» | Названия полей/кнопок = то, что человек сам скажет вслух; нет `user_id`, `payload`, `status: APPROVED` в тексте |
| 3 | **Дай контроль и свободу** — пользователь может отменить, вернуться, передумать; «выход» всегда под рукой | Ошибки и случайные клики неизбежны; тупик = потеря доверия | Есть undo/«отмена»/назад; нет безвыходных состояний без явного выхода |
| 4 | **Согласованность и стандарты** — одно действие = одно название, один вид, одно место | Пользователь учит систему один раз, дальше полагается на память | Термины, цвета статусов, кнопки одинаковы на всех экранах; не смешиваются паттерны |
| 5 | **Предотвращай ошибки** — лучше не дать ошибиться, чем сообщить об ошибке | Каждая ошибка = время, страх, откат | Опасные действия подтверждаются; ввод ограничен/подсказан; кнопка деструктивного действия не рядом с главной |
| 6 | **Узнавание вместо вспоминания** — видимые подсказки, не нагрузка на память | Человек хуже вспоминает, чем узнаёт | Контекст, лейблы, подсказки на экране; не нужно держать данные из прошлого шага в голове |
| 7 | **Гибкость и эффективность** — частые действия быстрее, есть сокращения | Опытный пользователь не должен проделывать лишние шаги | Повторяющиеся сценарии в 1 клик; массовые действия вместо поштучных |
| 8 | **Эстетика и минимализм** — убрать всё, что не помогает задаче | Каждый лишний элемент конкурирует за внимание | Один акцент, пустое место несёт смысл, нет декора ради декора |
| 9 | **Понятные ошибки с решением** — что случилось, почему, что делать | Вагая ошибка не даёт исправиться | Текст ошибки = «что + почему + как починить», обычным языком, не код |
| 10 | **Помощь и документация рядом** — помощь там, где она нужна, а не в FAQ | Пользователь ищет ответ в момент затруднения | Подсказки у сложных полей; справка доступна с места использования |
| 11 | **Иерархия читается за 5 секунд** — размер, вес, цвет, отступы ведут глаз | Взгляд сначала сканирует, потом читает | Заголовок > подзаголовок > тело различимы по весу/размеру; главное действие визуально главнее второстепенных |
| 12 | **Доступность = качество, не опция** — контраст, фокус, клавиатура, подписи | Значимая часть пользователей иначе просто не сможет пользоваться; это и требование WCAG | Контраст текста ≥ 4.5:1, видимый `:focus-visible`, тач-зона ≥ 44px, всё интерактивное с именем для скринридера |

**Законы UX, стоящие за правилами (шпаргалка):**
- **Fitts's Law** — крупнее/ближе цель = быстрее попадание → большие кнопки у главного действия, не прятать в меню.
- **Hick's Law** — больше вариантов = дольше решение → группируй, сокращай выбор, дефолты.
- **Jakob's Law** — пользователи ждут поведения как на знакомых сайтах → используй стандартные паттерны.
- **Miller's Law (7±2)** — разбивай длинное на чанки (сегменты, шаги, группы).
- **Tesler's Law** — сложность неуничтожима, её можно только перенести → интерфейс берёт сложность на себя.
- **Doherty Threshold** — отклик < 400 мс удерживает внимание → скелетоны/оптимистик вместо пустоты.
- **Aesthetic-Usability Effect** — аккуратное воспринимается как более удобное → это критерий жюри UX/UI.
- **Peak-End Rule** — помнят пик и конец → конец сценария должен быть приятным (явный успех).
- **Postel's Law** — будь либерален ко входу, строг к выходу → прощай форматы ввода, отдавай чистый результат.

## 2. Анти-паттерны и тёмные паттерны

### 2.1 Обычные анти-паттерны интерфейса

| Анти-паттерн | Чем плох | Как правильно |
|---|---|---|
| Placeholder вместо label | Подпись исчезает при вводе — не видно, что заполняешь; скринридеры теряют поле | Видимый `label` над полем; placeholder — только пример формата |
| Кнопка без feedback (клик «проглочен») | Пользователь не знает, сработало ли, жмёт повторно | `disabled`/спиннер во время запроса + тост/сообщение об успехе |
| Пустое состояние «здесь ничего нет» | Мёртвый экран, нет пути дальше | Объяснить, почему пусто, и дать призыв к действию |
| Сообщение об ошибке без решения | «Ошибка 500» — пользователь в тупике | Что случилось + что сделать (повторить/поправить поле) |
| Слабая иерархия (всё одинаковое) | Непонятно, что главное, куда смотреть | Один визуальный акцент; вес/размер/цвет кодируют важность |
| «Прыгающая» вёрстка (CLS) | Элементы смещаются при загрузке → клик «мимо» | Резервировать место под загружаемый контент (скелетоны, размеры) |
| Перегруз экрана | Слишком много выбора = паралич решения | Минимализм, поэтапное раскрытие, дефолты |
| Недосказ (непонятно, что будет) | Кнопка «OK» без контекста — страх нажать | Глагол-действие в кнопке: «Создать выезд», не «Submit» |
| Ложное/декоративное действие | Кнопка выглядит активной, но ничего не делает | Только реальные действия; отключённое визуально отличается |
| Микротекст-заглушка (`Lorem`, «тест») | Выглядит недоделанным, подрывает доверие | Реальные формулировки с самого начала |
| Таблица как `div` без семантики | Теряется доступность, сорт-сть, копирование | Семантический `<table>`/список, заголовки колонок |
| Длинный список без поиска/группировки | Прокрутка как трение | Поиск, фильтры, группировка, пагинация при росте |
| Нет фокуса с клавиатуры | Нельзя пользоваться без мыши | Видимый `:focus-visible` у всех интерактивных элементов |
| Клик по `<div onClick>` | Нет фокуса/Enter/роли для скринридера | Настоящие `<button>`/`<a>`, или `role` + `tabindex` + обработчик клавиш |
| Цвет как единственный носитель смысла | Дальтоники/скринридер не различают | Цвет + текст/иконка/форма одновременно |
| Время в формате системы (`2026-09-27T13:00:00Z`) | Нечитаемо | Локальный формат: «27.09.2026, 13:00» |
| Отключённая кнопка без объяснения | Непонятно, почему нельзя | Объяснить причину рядом или включать с подсказкой |

### 2.2 Тёмные (обманные) паттерны — не использовать (Brignull, deceptive.design)

| Паттерн | Суть | Почему вреден |
|---|---|---|
| Sneaking / скрытое добавление | Подсунуть доп. товар/подписку незаметно | Обман, юридически рискованно |
| Forced action | Заставить сделать лишнее ради цели | Манипуляция |
| Preselection | Заранее отмеченные невыгодные чекбоксы | Навязанное согласие (в т.ч. ПДн!) |
| Confirm-shaming | «Нет, я не хочу скидку» — стыдить за отказ | Давление, потеря доверия |
| Bait and switch | Кнопка делает не то, что обещает | Прямой обман |
| Hard to cancel / roach motel | Легко подписаться, трудно отписаться | Удержание силой |
| Hidden costs | Цена всплывает в конце | Недоверие к бренду |
| Disguised ads | Реклама под видом контента | Обман |
| Fake urgency/scarcity | «Осталось 2 места» без реальных данных | Манипуляция; в ClassGo явно помечено как «не делать» |
| Trick questions | Запутанная формулировка галочки | Обман |

> Для ClassGo особенно важен **preselection** и **forced action** в согласиях (ПЭП/ПДн): согласие родителя
> должно быть осознанным, без предотмеченных галочек и без «стыда» за отказ. См. §6 находок.

## 3. Что чаще всего ломают по уровням

Различие уровней важно: стажёр ломает **доступность и состояния**, джун — **консистентность и сценарии**,
миддл — **крайние случаи и производительность**, AI-агент — **семантику и контент**.

### 3.1 Стажёр (знает вёрстку, не знает UX)
- Нет состояний: только «успешный» рендер, loading/empty/error отсутствуют.
- Кнопки без `disabled`/feedback — двойные отправки, «проглоченные» клики.
- Placeholder вместо label, форма без валидации и сообщений об ошибках.
- Отсутствие фокуса/клавиатуры; `div onClick`; цвет без текста.
- Таблицы и списки как вёрстка без семантики и поиска.
- Кнопки «Submit»/«OK» вместо действия; тексты-заглушки.

### 3.2 Джун (знает паттерны, не видит систему)
- Разнобой: одна кнопка зовётся по-разному на экранах; статусы имеют разные цвета.
- Нет undo/подтверждения у деструктивных действий.
- Пустые состояния «ничего нет» без пути дальше.
- Ошибки без причины и решения; тосты с техническим текстом.
- Слабые edge cases: пустой список, один элемент, очень длинные строки, `null`-даты.
- Тач-зоны < 40px, интерактив без hover/focus-состояний.

### 3.3 Миддл (знает систему, пропускает контекст и производительность)
- Не думает о воспринимаемой производительности (спиннер вместо скелетона, нет оптимистика).
- Не резервирует место → CLS/прыжки при загрузке.
- Перегруз: пытается вместить все данные на один экран без группировки.
- Не документирует дизайн-токены → дрейф системы между экранами.
- Игнорирует `prefers-reduced-motion`, тёмную тему, масштаб шрифта.
- Не проверяет пустой/ошибочный сценарий в реальном флоу, только «счастливый путь».

### 3.4 AI-агент (отдельно — самая частая и самая заметная категория)
- **Семантическая глухота**: `status: APPROVED`, `student_id`, `payload` как текст в UI вместо человеческого.
- **Только «счастливый путь»**: генерирует успешное состояние, забывает loading/empty/error/focus/aria.
- **Форма без доступности**: валидация видна визуально, но не озвучивается скринридеру; модалка открывается без переноса фокуса.
- **Декоративная кнопка/действие**: выглядит кликабельно, но ничего не делает; или ложный прогресс.
- **Контент-заглушки и сгенерированный «красивый» текст**: microcopy с неверными референтами, фейковая точность чисел.
- **AI-дизайн-теллы** (из скилла `design-taste-frontend`): фиолетовый градиент, три одинаковые карточки, Inter по умолчанию, emoji вместо иконок, `·`-разделители, `—`, «eyebrow»-ALL-CAPS над каждой секцией, моно-шрифт «для мелких данных» ради стиля, центрированный герой.
- **Нет самопроверки**: не прогоняет экран «глазами» по чек-листу (см. §5), не смотрит скриншоты.

## 4. Практические чек-листы по темам

### 4.1 Формы и валидация
- Label над полем; placeholder только как пример формата.
- Валидация инлайн и у поля, не глобальным тостом.
- Ошибка = что не так + как исправить; поле с ошибкой подсвечено и связано (`aria-describedby`/`aria-invalid`).
- Кнопка отправки: активна/неактивна по валидности, во время отправки `disabled` + текст «Отправляем…».
- После успеха — явное подтверждение и, если уместно, возврат/следующий шаг.
- Не терять введённое при ошибке; дефолты разумны (Hick's Law).

### 4.2 Пустые, загрузочные, ошибочные состояния
- **Empty**: объяснить почему пусто + призыв к действию («Создайте первый выезд в каталоге»).
- **Loading**: скелетон, повторяющий форму будущего контента (лучше спиннера — снижает ощущение ожидания).
- **Error**: контекстно (inline для форм, тост для транзиентного); что + почему + что делать; кнопка «Повторить».

### 4.3 Микротекст (microcopy)
- Кнопки — глагол-действие: «Создать выезд», «Скачать приказ», не «Submit»/«OK».
- Имя действия одинаково на всём флоу: «Опубликовать» → тост «Опубликовано».
- Ошибки не извиняются и не туманны; не «произошла ошибка», а «Не удалось загрузить: сервер недоступен. Повторите».
- Тон — sentence case, обычные слова, активный залог, без filler.

### 4.4 Дизайн-токены и шкалы
- Одна палитра и один радиус на проект; акцент — один; статусы — смысл, не декор.
- Тип-шкала с фиксированными ступенями; интервалы от одной базы (8px).
- Числа с `tabular-nums` (выравнивание колонок); без декоративного моно.

### 4.5 Тач-зоны и mobile
- Тач-цель ≥ 44×44 CSS px (WCAG 2.5.8 даёт минимум 24px с исключениями; 44px — цель для аудитории 50+).
- Кнопки `min-height` 44px, вкладка 44px, место в сетке — 44×44 (в ClassGo уже применено).
- Основной текст — **1rem (16px) минимум** и масштабируется системной настройкой (`html { font-size: 100% }`).
- Проверять на узком экране (≤ 420px) и при **+200 % текста**: переносы, обрезка, горизонтальный скролл.
- Не `h-screen`, а `min-h-[100dvh]` — чтобы не прыгало из-за адресной строки.

### 4.6 Воспринимаемая производительность
- Скелетон вместо пустоты; оптимистик для быстрых действий.
- Анимация — только `transform`/`opacity`, ≤ 300 мс, под `prefers-reduced-motion` (детали: [`MOTION_AND_A11Y.md`](MOTION_AND_A11Y.md)).
- Резервировать место под контент (нет CLS).
- Отклик < 400 мс (Doherty); фоновое — с индикатором прогресса.

### 4.7 Состояния кнопок
- default / hover / active (тактильный сдвиг) / focus-visible / disabled (с объяснением или отключена осознанно) / loading.
- Главное действие визуально главнее; не два CTA с одинаковым намерением рядом.
- Текст не переносится на 2+ строки на десктопе.

### 4.8 Подтверждения и undo
- Деструктивное — подтверждение; лучше undo, чем подтверждение.
- После действия — явный результат (тост/инлайн), который можно понять без перечитывания.

### 4.9 Таблицы и длинные списки
- Семантическая таблица с заголовками; числа выровнены.
- Поиск/фильтр/группировка при росте; пагинация не раньше, чем реально нужно.
- Строка-действие — `<button>`, не `tr onClick`.

### 4.10 Доступность и фокус
- Контраст текста ≥ 4.5:1 (крупный ≥ 3:1); не цвет как единственный носитель смысла.
- Видимый `:focus-visible` у всего интерактивного; порядок табуляции логичный.
- Всё интерактивное имеет доступное имя (`aria-label`/текст); иконки `aria-hidden`.
- `prefers-reduced-motion` уважать; масштаб шрифта не ломает вёрстку.

## 5. Чек-лист перед сдачей UI (глазами и кодом)

Прогонять по каждому экрану. «Глазами» — скриншот/живой прогон; «кодом» — чтение `*.tsx`/`*.css`.

### Глазами
- [ ] Иерархия читается: главное действие видно сразу, заголовки не спорят.
- [ ] Все состояния есть: загрузка, пусто, ошибка, успех — не только «счастливый путь».
- [ ] Каждое действие даёт обратную связь (нет «проглоченных» кликов).
- [ ] Пустое состояние объясняет и ведёт дальше.
- [ ] Ошибки понятны и предлагают решение.
- [ ] Тексты без заглушек, без `Lorem`, без технических идентификаторов.
- [ ] Ничего не прыгает при загрузке (нет CLS).
- [ ] Узкий экран (≤ 420px) и тач-зоны ≥ 40px.
- [ ] Контраст достаточен, статусы различимы и по цвету, и по тексту.
- [ ] Один акцент, нет AI-дизайн-теллов (фиолетовый градиент, 3 карточки, ALL-CAPS, `·`/`—`, моно).

### Кодом
- [ ] Интерактив — `<button>`/`<a>`, а не `div/tr onClick`; есть `type="button"`.
- [ ] `:focus-visible` определён для всех контролов.
- [ ] Поля форм имеют `label`/`aria-label`; ошибки связаны через `aria-describedby`/`aria-invalid`.
- [ ] Иконки `aria-hidden`; декоративное не озвучивается.
- [ ] Значения форматируются локально (дата/время/деньги), а не сырым ISO.
- [ ] Кнопки имеют `disabled`/loading во время запроса; нет двойной отправки.
- [ ] `prefers-reduced-motion` обработан.
- [ ] Пустой/нулевой/ошибочный рендер не падает (guards на `null`/пустой массив).
- [ ] Семантические элементы там, где таблицы/списки (не `div`-таблицы).

## 6. Самопроверка: UX-нарушения в мини-аппе ClassGo

Прогон экранов `miniapp/src/screens/*.tsx` и `miniapp/src/styles.css` по §5. Находки с `file:line` и
приоритетом. Код **не менялся** — это список для следующей задачи (дублируется в `classgo-TODO.md`).

### P0 — чинить до защиты (ломает понимание/действие/доступность)

1. **Кнопки «Напомнить»/«Сформировать приказ»/«Создать выезд» отключаются по одному флагу `busy`, но нет
   визуального loading-состояния у других действий в том же блоке.** [`DashboardScreen.tsx:161`](miniapp/src/screens/DashboardScreen.tsx:161),
   [`DashboardScreen.tsx:164`](miniapp/src/screens/DashboardScreen.tsx:164) — `disabled={busy}` выключает сразу
   обе кнопки (и «Сформировать приказ», и «Напомнить»), хотя выполняется одна; пользователь видит, что всё
   «умерло», без указания, что именно идёт. Нет текста «Напоминаем…»/«Формируем…» как у
   [`CatalogScreen.tsx:159`](miniapp/src/screens/CatalogScreen.tsx:159) («Создаём…»). Нужен индикатор у
   конкретной кнопки, а не глобальный `busy`.

2. **Поле поиска в каталоге без `label`/`aria-label` — placeholder как единственная подпись.**
   [`CatalogScreen.tsx:72`](miniapp/src/screens/CatalogScreen.tsx:72) — `<input type="text" placeholder="поиск по
   названию">` внутри `<label>` без текста; скринридер не получит имя поля (только placeholder). Нарушает §4.1/§4.10.

3. **Чекбоксы «Пушкинская карта»/«Бесплатные» не озвучивают состояние смены при фильтрации каталога.**
   [`CatalogScreen.tsx:88`](miniapp/src/screens/CatalogScreen.tsx:88), [`CatalogScreen.tsx:92`](miniapp/src/screens/CatalogScreen.tsx:92) —
   фильтр перезагружает список через `useEffect` [`CatalogScreen.tsx:26`](miniapp/src/screens/CatalogScreen.tsx:26),
   но нет ни `aria-live`, ни видимого состояния «загрузка» — пользователь скринридера не узнает, что список
   обновился; зрячий не видит промежуточного «грузится».

4. **Загрузка каталога и дашборда не показывают скелетон — только «Ошибка каталога» при фейле; нет состояния
   «загружаем» для каталога.** [`CatalogScreen.tsx:26`](miniapp/src/screens/CatalogScreen.tsx:26) — события грузятся
   без индикатора; при пустом результате показывается «Под фильтры ничего не подошло»
   [`CatalogScreen.tsx:133`](miniapp/src/screens/CatalogScreen.tsx:133) даже пока идёт первичная загрузка (список ещё
   пуст). Скелетон `SkeletonLoader` есть только в [`App.tsx:256`](miniapp/src/App.tsx:256) для верхнего уровня.

5. **Отсутствует фильтр по дате/периоду каталога (заявлен в PRD UC-2) — ограничивает выбор.**
   [`CatalogScreen.tsx:28`](miniapp/src/screens/CatalogScreen.tsx:28) — параметры только `city/age/pushkin/free`.
   Это и продуктовый пробел (PRODUCT_GAPS №15), и UX: учитель не может сузить по дате.

### P1 — заметно улучшает удобство

6. **Отсутствует поиск ученика и фильтр строк по статусу в «Списке класса».**
   [`DashboardScreen.tsx:264`](miniapp/src/screens/DashboardScreen.tsx:264) — список 24+ человек без поиска/фильтра,
   прокрутка как трение (PRODUCT_GAPS §6.2).

7. **Нет дедлайн-таймера/обратного отсчёта в дашборде.** [`DashboardScreen.tsx:126`](miniapp/src/screens/DashboardScreen.tsx:126) —
   дедлайн показан только как дата «сбора ответов», без срочности «осталось N дн/ч» (PRODUCT_GAPS §6.3, P0).

8. **Кнопка «Отпускаю ребёнка» и «Не сможет поехать» — нет подтверждения перед отправкой согласия.**
   [`ParentScreen.tsx:178`](miniapp/src/screens/ParentScreen.tsx:178) — согласие (юридически значимая ПЭП) уходит по
   одному клику без подтверждения; при случайном нажатии «Отпускаю» решение уже зафиксировано. Нужен шаг
   подтверждения или undo.

9. **[ЗАКРЫТО] «Не сможет поехать» и селект причины на одном уровне с главной кнопкой — не было визуального
   разделения деструктивного действия.** `ParentScreen.tsx` — теперь согласие «Отпускаю ребёнка» залито
   primary-синим (`--accent`), а отказ «Не сможет поехать» — outline-красным (`.kv-btn.danger`, `--stop`) в
   зоне `.kv-reject`, отбитой линией. См. [`COLOR.md`](COLOR.md) §6.

10. **«Билет куплен» без поля номера билета.** [`ParentScreen.tsx:204`](miniapp/src/screens/ParentScreen.tsx:204) —
    бэкенд принимает `ticket_number`, UI не шлёт (PRODUCT_GAPS №9).

11. **Две кнопки загрузки файла «DOCX» и «PDF» с одинаковым намерением рядом** — [`DashboardScreen.tsx:180`](miniapp/src/screens/DashboardScreen.tsx:180),
    [`DashboardScreen.tsx:183`](miniapp/src/screens/DashboardScreen.tsx:183) — дублирующие действия «скачать приказ»
    в разных форматах; допустимо, но стоит сгруппировать как «Скачать приказ (DOCX/PDF)».

12. **Пустое состояние журнала выездов ведёт «во вкладку Каталог», но ссылки на вкладку нет.**
    [`ExcursionsScreen.tsx:18`](miniapp/src/screens/ExcursionsScreen.tsx:18) — текст «Соберите первый во вкладке
    „Каталог событий“» без кликабельного перехода; пользователь должен сам искать вкладку.

### P2 — полировка

13. **`ViewPanel`/`Footer` с техническими деталями (`platform`, `deviceName`, `MAX version`, «запущено вне MAX»)
    видны всем.** [`App.tsx:277`](miniapp/src/App.tsx:277) — это отладочная информация, не нужна конечному
    пользователю (учителю/родителю); уместно только вне MAX-режима демо.

14. **Нет `aria-live` для алертов (тостов) — смена `msg` не озвучивается.** [`DashboardScreen.tsx:173`](miniapp/src/screens/DashboardScreen.tsx:173),
    [`CatalogScreen.tsx:99`](miniapp/src/screens/CatalogScreen.tsx:99), [`ParentScreen.tsx:119`](miniapp/src/screens/ParentScreen.tsx:119) —
    сообщения «Напоминания отправлены»/«Приказ сформирован» визуальны, но скринридер их не анонсирует.

15. **Чипы статусов «Пушкинская карта»/«Бесплатно»/«оплата в кассе» не имеют `aria-label`, смысл только текстом —
    ок, но статус «Сводка ответов» в рассадке читается только по цвету.** [`styles.css:487`](miniapp/src/styles.css:487) —
    `.kv-seat-GREEN` и др. различаются цветом; у кнопок мест `aria-label` есть
    [`DashboardScreen.tsx:213`](miniapp/src/screens/DashboardScreen.tsx:213), но в полосе прогресса
    [`DashboardScreen.tsx:147`](miniapp/src/screens/DashboardScreen.tsx:147) сегменты цветом без текста — есть
    `role="img"` и `aria-label` (ок), но счётчики цветом [`DashboardScreen.tsx:154`](miniapp/src/screens/DashboardScreen.tsx:154)
    — цвет + текст одновременно, приемлемо.

16. **Иконки нарисованы вручную (stroke-SVG), а не из библиотеки.** [`icons.tsx:1`](miniapp/src/icons.tsx:1) — по
    скиллу `design-taste-frontend` это «hand-rolled SVG», discouraged; но для 16px-набора и кириллического домена
    приемлемо. Отметить как осознанное решение, не баг.

17. **`text-wrap: pretty` и `max-width: 24ch` у hero-заголовка** [`styles.css:71`](miniapp/src/styles.css:71) — ок, но
    длинные названия событий могут обрезаться без многоточия; проверить на реальных длинных названиях.
