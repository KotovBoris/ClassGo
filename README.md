# ClassGo

Мини-приложение и чат-бот в MAX для классного руководителя: собрать класс на выезд в музей или театр.
Учитель выбирает событие, родители отвечают кнопкой в чате, учитель видит, кто едет, собирает билеты
от семей и получает пакет документов для директора.

Деньги через сервис не проходят: билет семья покупает сама на сайте или в кассе площадки.

- Стенд: https://213.193.198.71 (выкачен из ветки `final-defense`). Работает внутри MAX, в обычном браузере показывает «Откройте ClassGo в MAX» (раздел 12).
- Бот: [@t158_hakaton_max_bot](https://max.ru/t158_hakaton_max_bot). Быстрее всего проверить так: «Начать» → «Попробовать демо».
- Что изменилось к финалу: [docs/FINAL_CHANGES.md](docs/FINAL_CHANGES.md).

## 1. Назначение

Школьный выезд (музей, театр, событие по «Пушкинской карте») обычно собирают в чате класса и в таблице:
кто идёт, кто дал согласие, у кого есть билет, кого нет на сборе. ClassGo ведёт выезд от выбора события
до списка группы, приказа и переклички в день выезда.

Пользователи: классный руководитель собирает выезд, родитель отвечает за своего ребёнка и присылает билет.
Директор получает документы от учителя, своей роли в сервисе у него нет.

## 2. Основной сценарий

Первый экран — выбор роли: «Я классный руководитель», «Я родитель» или «Попробовать демо» (`Welcome.tsx`).
Роль сохраняется на сервере (`POST /api/v1/me/role`). Если человек и учитель, и родитель, вверху главного
экрана есть переключатель «Я учитель / Я родитель».

### Учитель

1. **Класс** (`NewClass.tsx`): номер и буква, школа, ФИО учителя, телефон учителя (в мини-приложении
   обязателен, его видят родители). Учеников можно добавить тремя способами:
   - «Родители сами» — списка нет, учитель указывает только число детей по журналу, родители присылают заявки по ссылке класса;
   - «Вставить список» — строки «ФИО ученика; телефон родителя; ФИО родителя»;
   - «Файл Excel» — `.xlsx` или `.csv`, образец: [artifacts/sample_class_import.csv](artifacts/sample_class_import.csv).

   Часовой пояс класса берётся с телефона учителя.
2. **Подключение родителей** (`ClassScreen.tsx`, `JoinScreen.tsx`, `joins.py`). Одна ссылка и QR на весь класс.
   Родитель открывает ссылку в MAX и подтверждает номер (`requestContact`, подпись номера проверяет сервер).
   - Номер есть в списке класса — родитель подключается сразу.
   - Номера нет — родитель вписывает ребёнка, учитель подтверждает заявку кнопкой в боте или на экране класса
     и может поправить ФИО. Есть «Подтвердить все».
   - Если у ученика из списка уже есть родитель, заявку подтверждает только отдельная кнопка
     «Это второй родитель — подключить», а «Подтвердить все» её пропускает.
   - Открытых заявок не больше 3 от одного родителя и 60 на класс.
3. **Новый выезд** (`NewTrip.tsx`), три шага:
   - «Куда идём?» — событие из афиши Казани (поиск, фильтры «Бесплатные», «Пушкинская карта», возраст по классу) или «Свой вариант»;
   - «Когда и как?» — дата, время сбора и возвращения, место сбора, транспорт, помощник руководителя (обязательно), срок ответа (по умолчанию за 3 рабочих дня до выезда);
   - «Проверьте приглашение» — как его увидят родители и сколько семей его получат.

   После «Отправить родителям» каждый подключённый родитель получает в чат бота личное приглашение с кнопками.
4. **Экран выезда** (`TripScreen.tsx`). Сводка ответов: «отпускают», «ещё не ответили», «не смогут» и полоса
   «Ответили X из Y». Ниже — списки детей; в карточке ученика видно, кто, когда и как ответил, и телефон родителя.
   Кнопка «Напомнить N родителям». Для семей без MAX — бумажный бланк: учитель отмечает «Бланк: отпускают» или
   «Бланк: не сможет», в реестре такой ответ помечен как бумажный. Когда ответили все, бот один раз пишет учителю
   и предлагает документы.
5. **Документы** (`documents.py`), PDF для печати и DOCX для правки: проект приказа (по письму Минпросвещения
   от 16.06.2022 № 06-836), список группы, рабочий список с телефонами родителей, реестр согласий (кто, когда,
   каким способом, хеш условий выезда), ведомость инструктажа и памятка, бумажные бланки для не ответивших,
   образец пунктов Порядка получения согласий для администрации. В список и приказ попадают только те, кого
   отпустили. В MAX кнопка «В чат MAX» присылает PDF и DOCX файлами в чат с ботом, вне MAX файлы скачиваются
   кнопками «PDF» и «DOCX».
6. **День выезда** (блок появляется в день выезда, в демо-классе — сразу): перекличка «Есть / Нет»,
   «Группа выехала», «Группа вернулась». Родители получают сообщения в MAX; родителю отсутствующего ребёнка бот
   пишет, что тот не пришёл на сбор, и даёт телефон учителя. Повторное нажатие сообщений не рассылает.
   «Отменить выезд» — родители получают сообщение об отмене; после отметки «Группа выехала» отменить нельзя.

### Родитель

1. Приглашение приходит в чат бота: чей ребёнок и класс, кто зовёт, где и когда, цена билета и можно ли
   платить «Пушкинской картой» (по дате рождения ребёнка, 14–22 года), «Платить в чате ничего не нужно»,
   телефон учителя. Кнопки называют ребёнка: «✅ Да, Тимур пойдёт», «Нет, Тимур не пойдёт», и ещё «Подробнее»
   (открывает мини-приложение).
2. Перед первым ответом — два шага: соглашение о простой электронной подписи (ст. 9 63-ФЗ) и отдельное согласие
   на обработку персональных данных (ст. 9 152-ФЗ). Можно отказаться и отвечать на бумаге. Пока соглашение
   не принято, API ответ не принимает (409).
3. Отказ — с причиной из списка: «Личные причины», «Семейные обстоятельства», «Другие планы».
4. «Изменить ответ» доступно до времени сбора. Прежний ответ действует, пока не выбран новый.
   Учитель может снять только свои бумажные отметки.
5. Если у ребёнка двое подключённых родителей, второй получает сообщение о решении первого. Два одновременных
   нажатия не перезаписывают друг друга: запись идёт условным UPDATE (`services.apply_consent`).
6. «Позвать второго родителя» даёт одноразовую ссылку на сутки. По ней второй взрослый отправляет заявку,
   её подтверждает учитель, уже подключённые родители получают сообщение.
7. Напоминания тем, кто не ответил: автоматически за 72, 24 и 12 часов до срока (только самое срочное,
   не раньше чем через 6 часов после приглашения) и кнопкой учителя (не чаще раза в 12 часов). С 21:00 до 08:00
   по часам родителя не пишем: берём пояс телефона, если родитель открывал мини-приложение, иначе пояс школы.
   Выключить напоминания — переключателем в мини-приложении или `/mute` в боте, включить — `/unmute`.
   Приглашения на новые выезды приходят и при выключенных напоминаниях.
8. «Отозвать согласие» отвязывает MAX от детей и удаляет присланные родителем файлы билетов. Уже данные ответы
   остаются в реестре школы.

Команды бота: `/start`, `/trips` (выезды ребёнка с кнопками), `/mute`, `/unmute`, `/help`. В групповых чатах бот
ничего не принимает и туда не отвечает (`bot._on_message`).

### Билеты от родителей

- Родитель, ответивший «Да», присылает фото или PDF билета (или скриншот чека): в чат бота после кнопки
  «📎 Отправить фото билета» или в мини-приложении. Если файл пришёл в чат без кнопки, бот спрашивает,
  к какому выезду его сохранить. Новый файл заменяет прежний.
- Проверка файла (`tickets.normalize`): тип определяется по содержимому, размер до 10 МБ. Фото поворачивается
  по EXIF, прозрачный фон становится белым, длинная сторона уменьшается до 2400 px, файл пересохраняется в JPEG
  без EXIF (геометка пропадает). PDF — от 1 до 10 страниц, без пароля. Иначе родитель получает понятный отказ.
- Учитель видит «Прислали билет: X из Y», листает билеты («Показать билеты») и получает все одним PDF:
  обложка, билеты по алфавиту с подписью, чей билет, последний лист «Для учителя — не показывать на входе» —
  у кого билета нет и чей файл не открылся. В MAX этот PDF приходит файлом в чат («Все билеты в чат»).
- Ссылки на файлы подписаны HMAC и привязаны к самому файлу (`tickets.signed_url`): ссылка на билет живёт сутки,
  на PDF класса — 10 минут. Приказ тоже скачивается по подписанной ссылке, она живёт 10 минут (`main._download_url`).
- Файлы удаляются через 7 дней после даты выезда (`tickets.purge_old`), при отзыве согласия родителем,
  при удалении ученика и демо-класса.

### Демо

«Попробовать демо» (в боте или на первом экране) создаёт личный демо-класс 7Б (`demo.py`): пользователь —
его учитель и родитель ученика Тимура Сафина, остальные 11 родителей виртуальные.

- Сразу есть пример выезда со сбором ответов: 7 согласий (у 5 — билеты-образцы от виртуальных родителей),
  1 отказ, 4 без ответа, в том числе Тимур. Приглашение по Тимуру приходит пользователю в чат бота.
- Новый выезд в демо-классе закрывает пример без рассылки. Виртуальные родители отвечают сами в течение
  минуты: двое молчат (чтобы было кому напомнить), один отказывается, на платный выезд часть присылает билеты.
- Билет-образец зависит от события: у спектакля — зал, ряд и место, у музея — входной билет на сеанс.
  На каждом надпись «ОБРАЗЕЦ · демо-данные ClassGo · для входа недействителен».
- «Начать демо заново» пересоздаёт класс. Ссылка демо-класса постоянная: кто откроет её в MAX (например,
  по QR на защите), становится родителем свободного ученика без подтверждения номера.

## 3. Состав и архитектура

Сервисы в `compose.yaml`:

| Сервис | Что внутри |
|---|---|
| `backend` | Python 3.12, FastAPI: REST API `/api/v1/*`, бот MAX (long polling или webhook) в том же процессе, фоновые задачи, генерация DOCX и PDF, SQLite |
| `miniapp` | React 19 и `@maxhub/max-ui`, сборка Vite; nginx отдаёт статику и проксирует `/api/`, `/docs`, `/openapi.json`, `/healthz`, `/webhook/` на backend |
| `db` | PostgreSQL 16, запускается только с профилем `postgres` |

Модули `backend/app`:

| Файл | Что делает |
|---|---|
| `main.py` | REST API, права доступа, вебхук, запуск фоновых задач |
| `bot.py` | бот: приглашения, ответы кнопками, соглашение, билеты из чата, заявки родителей, напоминания, документы в чат |
| `services.py` | правила: ответ и его изменение, сводка ответов, кому и когда напоминать, второй родитель |
| `auth.py`, `max_validate.py` | кто делает запрос: подпись initData MAX и подпись номера телефона |
| `tickets.py` | билеты: проверка файла, хранение, подписанные ссылки, PDF класса, билеты-образцы для демо |
| `joins.py` | заявки родителей «добавьте моего ребёнка» |
| `demo.py` | демо-класс и виртуальные родители |
| `documents.py` | пакет документов DOCX и PDF |
| `timeutil.py` | время школы и родителя |
| `max_client.py` | клиент MAX Bot API: сообщения, загрузка файлов, скачивание вложений |
| `catalog_seed.py` | афиша и стартовые демо-данные |
| `models.py`, `schemas.py`, `db.py`, `config.py` | модель данных, схемы API, подключение к базе, настройки |

Фоновые задачи (`main.lifespan`):

- опрос MAX (`_poll_loop`) — если задан токен и `MAX_BOT_MODE=polling`; при старте регистрирует команды бота;
- напоминания и уборка (`_reminder_loop`, раз в `REMINDER_INTERVAL_SECONDS`): автонапоминания, удаление старых файлов билетов и решённых заявок — только если бот включён;
- ответы виртуальных родителей демо-классов (`_demo_loop`, каждые 2 секунды) — всегда.

Мини-приложение (`miniapp/src`): `App.tsx` выбирает роль и экран по `start_param`, `api.ts` передаёт initData
в заголовке `X-Max-Init-Data` и пояс телефона в `X-Timezone`, `max.ts` — обёртка над MAX Bridge, экраны — `screens/`.

### Кто делает запрос

Строгий режим (`auth.strict_auth`) включается, когда задан токен бота или `MAX_VALIDATE_INIT_DATA=true`:

- пользователь определяется только по initData из заголовка `X-Max-Init-Data`; подпись проверяется токеном бота, `user_id` берётся из неё;
- поддельная подпись или initData старше `INIT_DATA_MAX_AGE_SECONDS` (сутки) — 401;
- без заголовка — аноним; параметр `?user_id` игнорируется.

Без токена (локальная проверка и тесты) пользователь берётся из `?user_id=`. Мини-приложение вне MAX
подставляет его само: из адресной строки или случайный номер, сохранённый в браузере.

Права (`main.py`: `_can_edit_class`, `_can_view_class`, `_is_parent_of`): учитель видит и меняет свои классы
и выезды; родитель видит выезды и билеты только своих детей и отвечает только за них. Классы без владельца
(стартовые демо-данные) вне строгого режима доступны всем, в строгом — никому.

## 4. Запуск одной командой

Из корня репозитория:

```bash
docker compose up --build
```

После сборки открыть http://localhost:8080. Файл `.env` не обязателен: без него бот выключен, а ник бота
в ссылках-приглашениях пустой. Чтобы ссылки вели на бота, перед запуском выполните `cp .env.example .env`
(токен можно оставить пустым). Для живого бота впишите в `.env` `MAX_BOT_TOKEN`.

Без Docker: backend — `cd backend && uvicorn app.main:app --port 8000` (база по умолчанию `backend/data/classgo.db`),
мини-приложение — `cd miniapp && npm ci && npm run dev` (http://localhost:5173, `/api` проксируется на порт 8000).

## 5. Что нужно на машине

- Docker и Docker Compose 2.20 или новее (в `compose.yaml` используется `depends_on.required`).
- Без Docker: Python 3.12 и Node.js 20.
- Для проверки в мессенджере: аккаунт MAX. Бот на стенде уже работает. Для своего бота нужны токен и публичный
  HTTPS-адрес мини-приложения в настройках бота: `localhost` MAX не откроет.
- Логины и пароли не нужны: пользователя определяет MAX.

## 6. Переменные окружения

Образец — [.env.example](.env.example). Рабочих токенов в репозитории нет. `compose.yaml` передаёт в контейнер
`backend` только переменные из первой таблицы.

| Переменная | Зачем | В `compose.yaml` без `.env` | В `.env.example` |
|---|---|---|---|
| `MAX_BOT_TOKEN` | токен бота. Пусто — бот, сообщения, напоминания и строгий режим выключены | пусто | пусто |
| `MAX_API_BASE` | адрес Bot API | `https://platform-api2.max.ru` | то же |
| `MAX_BOT_MODE` | `polling`, `webhook` или `off` | `polling` | `polling` |
| `MAX_BOT_USERNAME` | ник бота в ссылках-приглашениях и кнопках открытия мини-приложения. После создания бота в MAX не меняется | пусто | `t158_hakaton_max_bot` |
| `MAX_WEBHOOK_SECRET` | секрет вебхука. В режиме `webhook` без него `/webhook/max` отвечает 503 | пусто | пусто |
| `MAX_WEBHOOK_URL` | читается в `config.py`, но код его не использует: подписку на вебхук сервис сам не оформляет | пусто | пусто |
| `MAX_CA_BUNDLE` | PEM с корневым сертификатом Минцифры для TLS до MAX; каталог `certs/` смонтирован в контейнер как `/certs` | пусто | `/certs/ca-bundle.pem` |
| `MAX_TLS_INSECURE` | не проверять TLS до MAX, только для отладки | `0` | `0` |
| `DATABASE_URL` | база | `sqlite:////app/data/classgo.db` | то же |
| `AUTO_SEED` | при старте положить в пустую базу афишу и стартовые демо-данные | `true` | `true` |
| `PUBLIC_BASE_URL` | начало подписанных ссылок на документы и билеты | `http://localhost:8080` | то же |
| `MINIAPP_BASE_URL` | читается в `config.py`, код его сейчас не использует | `http://localhost:8080` | то же |
| `LOG_LEVEL` | уровень логов | `INFO` | `INFO` |

Есть только в `config.py`. В Docker действуют значения по умолчанию; при запуске `uvicorn` из `backend/` их можно
задать в окружении или в `backend/.env`.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `MAX_VALIDATE_INIT_DATA` | `false` | строгий режим без включённого бота |
| `INIT_DATA_MAX_AGE_SECONDS` | `86400` | сколько секунд принимается initData в строгом режиме |
| `ADMIN_TOKEN` | пусто | заголовок `X-Admin-Token` для `POST /api/v1/admin/reset-demo` в строгом режиме; пусто — ручка закрыта |
| `DOWNLOAD_SECRET` | пусто | ключ подписи ссылок на файлы; пусто — выводится из токена бота |
| `FILES_DIR` | `./data/files` | каталог файлов билетов (в контейнере `/app/data/files`) |
| `POLL_TIMEOUT` | `30` | таймаут long polling, секунд |
| `REMINDER_INTERVAL_SECONDS` | `300` | как часто проверять напоминания и удалять старые файлы |

`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` (по умолчанию `classgo`) нужны только сервису `db` с профилем `postgres`.

PostgreSQL наружу не публикуется. На стенде (`scripts/deploy.sh`) перед мини-приложением стоит Caddy
на портах 80 и 443, порт 8080 наружу не открыт, backend слушает только `127.0.0.1:8000`.

## 10. Данные

- SQLite: файл `/app/data/classgo.db` в томе `classgo-data`. Схема создаётся при старте; в существующей базе SQLite
  недостающие таблицы и колонки добавляются автоматически (`db._ensure_columns`), миграций данных нет.
- Файлы билетов лежат в том же томе: `/app/data/files/tickets/<id выезда>/`.
- Что хранится (`models.py`):
  - школы, классы и доступ к ним;
  - ученики (ФИО, дата рождения);
  - родители: ФИО, телефон, роль, MAX ID, подтверждена ли связь с ребёнком, включены ли напоминания;
  - события афиши, выезды, участники выезда: ответ, причина отказа, кто подписал (имя, телефон, MAX ID, способ, время), отметка переклички, статус билета;
  - журнал действий `ConsentAudit`: согласие, отказ, изменение ответа, отметка и файл билета;
  - файлы билетов, заявки родителей, коды ссылок, журнал напоминаний;
  - профиль пользователя MAX: имя, роль, часовой пояс телефона, время принятия соглашения.
- Время в базе хранится в UTC. Людям время показывается по поясу школы: пояс класса берётся с телефона учителя
  при создании класса и копируется в выезд (`timeutil.py`). Тихие часы напоминаний считаются по поясу телефона
  родителя, если он известен.
- Ответ кнопкой — простая электронная подпись по соглашению, которое родитель принимает один раз
  (`UserProfile.terms_accepted_at`). В реестре согласий есть хеш условий выезда: если учитель поменяет условия,
  хеш изменится.
- Сроки хранения: файлы билетов удаляются через 7 дней после даты выезда (отметка «билет куплен» остаётся),
  решённые заявки — через 30 дней. Это делает фоновая задача, она работает при включённом боте.
  У отклонённой заявки телефон стирается сразу.
- Афиша помечена как подготовленные данные: поле `source` у события и `dataset.is_mock: true` в `GET /api/v1/meta`.

## 13. Что система отвечает

`GET /healthz` без токена:

```json
{"status": "ok", "version": "1.0.0", "bot_mode": "polling", "bot_enabled": false, "time": "…"}
```

На стенде `bot_enabled: true`.

Повторный ответ родителя (`POST /api/v1/excursions/{id}/consent`) статус не меняет:

```json
{"changed": false, "message": "Согласие уже подписано (<ФИО родителя>, <дд.мм> в <чч:мм>)."}
```

| Ситуация | Ответ |
|---|---|
| ответ до принятия соглашения | 409 «Сначала примите соглашение о подписи и дайте согласие на обработку данных» |
| ответ за чужого ребёнка | 403 «Ответить может только родитель этого ученика» |
| ответ после времени сбора | `changed: false`, «Выезд уже начался — ответ не принимается…» |
| строгий режим, поддельная или устаревшая подпись initData | 401 |
| строгий режим, без initData | аноним: пустые списки, 401 или 403 на действия |
| файл билета — не фото и не PDF | 422 «Нужна фотография (JPG, PNG) или PDF билета» |
| PDF с паролем или длиннее 10 страниц | 422 с объяснением |
| ссылка на файл с истёкшей подписью | проверяются права того, кто открыл; аноним получает 403 |
| `POST /webhook/max` не в режиме webhook | 404; с неверным секретом — 401 |
| `POST /api/v1/admin/reset-demo` в строгом режиме без верного `X-Admin-Token` | 404 |

Сводка выезда (`GET /api/v1/excursions/{id}/dashboard`) отдаёт `summary` с ключами `GREEN` (согласие, билет
не нужен или отмечен купленным), `YELLOW` (согласие, билет ещё не отмечен), `GREY` (нет ответа), `RED` (отказ),
а у выезда — `stats`: `total`, `answered`, `going`, `not_going`, `waiting`, `waiting_ticket`. Экран
«Сводка ответов» показывает три числа: «отпускают» (`going`, это `GREEN` + `YELLOW`), «ещё не ответили»,
«не смогут». Билет отмечается купленным, когда родитель присылает файл или вызывает `ticket-confirm`.

В приказ и список группы попадают только те, кого отпустили.

## 14. Ограничения

- **Афиша.** 16 событий Казани, подготовленных командой; PRO.Культура.РФ не подключён, афиша сама не
  обновляется. Под афишей в мини-приложении написано, что это демо-данные. Любое другое место можно
  указать через «Свой вариант».
- **Демо-данные помечены:** школы «(демо-данные)», тег «демо» у класса и выезда, надпись «ОБРАЗЕЦ» на билетах.
  ФИО и телефоны выдуманы.
- **Без токена бота** не работает всё, что идёт через MAX: приглашения, напоминания, сообщения учителю,
  документы и билеты в чат, сообщения в день выезда. Не запускается и фоновая уборка, поэтому файлы билетов
  по сроку не удаляются. Пользователь задаётся через `?user_id`, строгой проверки нет.
- **Подключение по номеру** работает только внутри MAX (`requestContact`), в браузере его не проверить.
  Ссылка демо-класса номера не требует.
- **Сообщения** уходят только родителям, подключённым в MAX. Остальным учитель отправляет ссылку в чат класса
  или даёт бумажный бланк.
- **Учитель.** Создать класс может любой пользователь MAX: работает ли он в этой школе, сервис не проверяет.
- **Подпись.** Ответ кнопкой — простая электронная подпись по соглашению с родителем. Равнозначной бумажной
  её делает Порядок, утверждённый школой; образец пунктов есть в пакете документов. Приказ — проект,
  решение принимает директор.
- **Билеты.** Сервис проверяет, что файл открывается, но не проверяет, что билет настоящий и куплен на этот выезд.
- **Срок ответа** не жёсткий: ответить можно до времени сбора. Автонапоминания после срока не уходят.
- **Часовой пояс** класса задаётся телефоном учителя при создании и в интерфейсе не меняется. У демо-класса — Москва.
- **База.** SQLite, миграций данных нет. PostgreSQL подключается профилем `postgres` (`make up-postgres`),
  но тесты и стенд работают на SQLite.
- **Ручки API без экранов.** От прежней версии остались: школы и доступ (`/schools`, `/schools/{id}/share`,
  `/classes/{id}/share`), публикация выезда и сообщение о неподключённых семьях в чат класса (`/publish`,
  `/tag-unactivated`; ID чата задаётся через `PATCH /classes/{id}`), код привязки ученика
  (`/students/{id}/link-code`), `/parents/search`, `/parent/confirm-link`, `/parent/claim` (в строгом режиме — 410).
- **Тесты интерфейса.** У мини-приложения автотестов нет (`npm test` проходит без тестов). `ui-e2e/`
  и `artifacts/openapi.yaml` описывают раннюю версию; актуальная схема API — `/openapi.json`.
- **Служебные настройки** (`ADMIN_TOKEN`, `DOWNLOAD_SECRET`, `MAX_VALIDATE_INIT_DATA` и другие из второй таблицы
  раздела 6) `compose.yaml` в контейнер не передаёт. Чтобы задать их в Docker, нужен свой `compose.override.yaml`.
- **Импорт класса** каждый раз создаёт новый класс; строки без ФИО пропускаются, в ответе — первые 20 пропущенных.

## 15. Остановка и повторный запуск

```bash
docker compose down
docker compose up --build
```

Удалить данные (базу и файлы билетов) и начать с чистых стартовых данных:

```bash
docker compose down -v
docker compose up --build
```

Перезапуск только API, без пересборки: `docker compose restart backend`. nginx находит новый адрес backend сам
(`resolver` в `miniapp/nginx.conf`).

С PostgreSQL: запуск — `make up-postgres`, остановка — `make down-postgres` (данные остаются в томе `classgo-pg`).

Выкладка стенда: `scripts/deploy.sh`, на сервере его копия `~/run.sh`; ветку задаёт `CLASSGO_BRANCH`
(`CLASSGO_BRANCH=final-defense ~/run.sh`). Скрипт останавливает все запущенные на машине контейнеры, том с базой
не трогает, после запуска прогоняет pytest и `scripts/e2e_docker.py`.
