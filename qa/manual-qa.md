# Ручное QA: что проверить человеку

Здесь только то, что нужно смотреть живым человеком в MAX. Остальное запускается командами из README.

## 0. Что уже проверено автоматически (делать вручную не нужно)

| Проверка | Команда | Результат |
|---|---|---|
| Модульные + интеграционные тесты ядра (13 шт.) | `cd backend && .venv313/bin/python -m pytest -q` | ✅ 13 passed |
| Сквозной сценарий бота через эмулятор протокола MAX (14 шагов) | `./backend/.venv313/bin/python scripts/e2e_agent.py` | ✅ 14/14 |
| Стек в Docker по HTTP (18 шагов) | `docker compose up -d --build && python3 scripts/e2e_docker.py` | ✅ 18/18 |
| Подключение к реальному MAX (`GET /me`, long polling) | `docker compose logs backend` | ✅ `MAX polling запущен, бот: Хакатон МАХ 158` |

## 1. Проверка бота в живом MAX (нужен аккаунт MAX)

**Что делать:**
1. Открыть MAX, найти бота **@t158_hakaton_max_bot** (или перейти `https://max.ru/t158_hakaton_max_bot`).
2. Нажать **«Начать»**.
3. Убедиться, что пришло приветствие «Здравствуйте, это бот «ClassGo»…» и две кнопки:
   «Открыть приложение» и «Мои выезды».

**Ожидаемое:** приветствие + кнопки. **Возможная проблема:** если приложение поднято
не на публичном HTTPS, кнопка «Открыть приложение» не откроет mini-app (нужен HTTPS-адрес).

**Что проверить после открытия mini-app:** см. п.2.

## 2. Мини-приложение внутри MAX (нужен HTTPS-хост)

**Что делать:** поднять решение на публичном HTTPS-адресе (например, через любой
туннель/VM), указать этот адрес в настройках бота (расширенные настройки → URL мини-приложения).

**Что смотреть:**
- Открывается каталог событий; фильтры «Пушкинская карта»/«Бесплатные» работают.
- Кнопка «Создать выезд» создаёт выезд, вкладка «Выезды класса» показывает дашборд «Сводка ответов».
- Кнопка «Сформировать приказ» — файл скачивается нативно (через MAX Bridge `downloadFile`).
- Внизу экрана видна строка «Платформа: ios/android/desktop · устройство: … · MAX: версия».
  Это подтверждает работу MAX Bridge.

**Почему вручную:** рендер мини-приложения и нативное скачивание файлов внутри
клиента MAX нельзя воспроизвести вне мессенджера (метод `downloadFile` «не работает в браузере» — документация MAX Bridge).

## 3. Нажатие кнопок согласия родителем (нужен аккаунт MAX)

**Что делать:** привязать родителя к ученику (кнопка «Привязать бота» в mini-app даёт
диплинк вида `https://max.ru/t158_hakaton_max_bot?start=bind_XXXX`). Перейти по нему из-под
родительского аккаунта MAX, затем получить напоминание (кнопка «Напомнить не ответившим»)
и нажать «✅ Отпускаю ребёнка».

**Ожидаемое:** в дашборде статус ребёнка меняется на «Готов», при повторном нажатии
появляется сообщение «Согласие уже подписано…».

**Почему вручную:** нужен реальный `user_id` MAX (в тестах подменяется эмулятором).

## 4. Отображение сертификатов Минцифры

**Что проверить:** в окружении проверяющего до `platform-api2.max.ru` нет TLS-ошибок.
Если в логе `CERTIFICATE_VERIFY_FAILED` — выполнить `python3 scripts/doctor.py` (он подскажет шаги).
Файл `certs/ca-bundle.pem` уже в репозитории и монтируется автоматически.

## 5. Внешние сервисы, которые сознательно замоделированы

> **Скачивание приказа в браузере.** Вне мессенджера кнопки «Сформировать приказ (DOCX)» и
> «Скачать PDF» используют обычную браузерную загрузку (нативный `WebApp.downloadFile` по
> документации MAX в браузере не работает). Под карточкой выезда дополнительно есть **прямые
> ссылки** «⬇ Скачать DOCX/PDF (прямая ссылка)» — они работают в любом окружении.

| Сервис | Статус в MVP | Что нужно для прода |
|---|---|---|
| Каталог PRO.Культура.РФ | модельные данные (снапшот, поле `source` у каждого события) | доступ к API PRO.Культура.РФ / СМЭВ |
| Оплата билета | ссылка на билетный шлюз музея (сервис денег не касается) | договор с учреждением культуры |
| Идентификация родителя | телефон/имя из бота и mini-app | валидация `initData` MAX Bridge (hash) на сервере |
| Пуш-напоминания | через MAX Bot API (`POST /messages`) | уведомления в проде через тот же канал |

## 6. Известные ограничения MVP (честно)

- Нет авторизации/ролей на API (демо-окружение). В проде — проверка `initData` MAX Bridge.
- Регистрация родителя по номеру телефона не подтверждена криптографически (MVP).
- Каталог не обновляется автоматически (модельный снапшот).
- Приказ формируется по типовому шаблону; юридическую выверку текста должен пройти юрист школы.
